## 製品概要
### 背景(製品開発のきっかけ、課題等）
昨今の就活では選考の過程でグループディスカッション(GD)が用いられることが多い。   
しかし、GDには致命的な欠点がある。  

それは司会の存在である。

司会はその他の役割に比べて明らかに異質な存在である。こなさないといけない役割も多く、必然的に膨大な発言量になる。  
司会を有利な立ち位置だと思ったことがある人も少なくないだろう。  
一方で、司会は自分の意見を言いづらく、負担が大きいという側面もある。司会の仕事で話す量が増えてしまうため、自分の意見まで言うタイミングを失いがちだ。  
また、司会は立場上、発言量の少ない人に話を振る必要があるが、相手の気持ちを思いやりながら話を円滑に進めるのは並大抵のことではない。   

このようにの司会の役割は不公平を生む。不幸も生む。 

そこで不公平と不幸をなくすため、進行役をAIに任せるという発想にたどり着いた。  
進行役をAIに任せれば、すべての参加者が平等な立場として心置きなく意見を出せる。  
言葉数が少ない人に話を振る際も、AIは心を痛めない。  
さらに、司会の進行の形式はある程度決まっているためAIに代替させても全く問題がない。

おまけに、このプロダクトをつかうことで、タイムキーパーという~~意味のわからない~~役割もする必要がなくなる。

### 製品説明（具体的な製品の説明）

就活グループディスカッション(GD)で、AIが進行役(ファシリテーター)を務めるWebアプリ。議論を聞き取り、「今、介入すべきか/見守るべきか」をAI自身が判断し、必要なときだけ音声で質問や論点整理、時間管理を行う。

PC1台を囲み、学生3〜4人とAIで議論する。企業側(採用担当者)はテーマと制限時間を設定するだけでよい。 

参加者が自己紹介をすると、声の特徴を一時的に登録し、以降の発話者を識別する。 

議論中の発話を文字起こしし、一定間隔や沈黙などをきっかけにAIが議論の状態を分析する。状態は「順調」「停滞」「脱線」「対立」「収束」などで判断する。 

状態に応じて、見守る、質問する、論点を整理する、比較の基準を問う、話題を戻す、発言していない人を指名する、残り時間を伝える、といった行動を選び、音声で話す。 

### 特長
#### 1. 特長1　「介入しない」を選べる自律判断 
「見守る」を正式な行動の1つにしている。盛り上がっている最中には割り込まず、介入しないと議論の質が下がる場面だけで話す。 

#### 2. 特長2　議論促進型(答えは与えない)
 論点整理、対立点の指摘、深掘り質問、脱線の修正、時間管理はするが、解決策や意見は出さず、特定の結論にも誘導しない。就活の評価の場として公平性を保つため。 
 
#### 3. 特長3 声の照合による発言機会の調整 
 自己紹介の声で発言者を識別し、長く発言していない人を、話題の区切りで名前を呼んで促す。識別の信頼度が低いときは、個人指名せず全体への呼びかけに切り替える。 

### 解決出来ること
進行役の負担と不公平感の軽減 

停滞、脱線、発言の偏りのその場での是正 

時間管理(残り時間の告知と終了) 

### 今後の展望
スマホアプリ化(今回はPC上のWebアプリ)。 

発言量を泡の大きさで見せる「しゃべりすぎメーター」。話しすぎの自覚を促し、議論の状態をビジュアライズする。 

書記(議事録・論点の自動整理)機能。 

参加者としてのAI(案出しや検索)。 

就活以外への展開(非就活GD、グループワーク、アイスブレイク、飲み会など)。非就活では意見をまとめる役割も許可するなど、場面ごとにルールを切り替える。 

課題解決型、アイデア創出型、意思決定型、計画立案型といった議論のタイプごとの流れに沿った進行。 

遮られた人に話を戻す機能(今回は検出が未実装)。 

「暗記でできること」ではなく「AIをうまく活用・フォローできること」を評価する新しい選考の形の提案。 
### 注力したこと（こだわり等）
過剰介入の防止: 発話中は話さない、沈黙が2秒以上ないと任意の介入はしない、直前の介入から一定時間は空ける、同じ人を連続で指名しない、といったルールを設けた。 

失敗時の安全側の動作: AIの応答が失敗したら「介入しない」に倒す。話者識別が不安定でも、全体の進行は止まらない。 

プライバシー: 録音は保存せず、声の特徴はメモリ上だけで保持して終了時に破棄する。発話本文は既定でログに残さない。 

実測に基づく方針転換: 話者分離が日本語のリアルタイム用途で機能しなかったため、自己紹介の声を登録して照合する方式に切り替えた。

### 独自技術

#### ハッカソンで開発した独自機能・技術
介入判断のハイブリッド設計: 判断をAIに任せる部分と、ルールで必ず守らせる部分を分けた。  

ルール層が、開始、時間告知、終了、発話中の抑止、クールダウンを管理する。 

LLMは1回の呼び出しで、議論の状態の分析と、行動の決定を同時に行う。 

LLMの出力は検証して補正する。許可されていない行動、名前が未確認の指名、長すぎる発話などは、補正または置換する。 

話題の区切りでの介入: 質問と回答のやり取りの最中は待ち、合意や沈黙などの区切りで話す。LLMの判断に5〜13秒かかるため、話す直前にもう一度、誰かが話し始めていないか確認し、話し始めていたら発話を破棄する。 

自己紹介による声の登録と照合: 日本語のリアルタイム話者分離が使えなかったため、自前の照合方式を実装した。 

評価の仕組み: 10種類の議論シナリオ(順調、停滞、脱線、対立、残り時間わずか、発言の偏り、独占、無発言者、遮り、低信頼度)でAIの判断を自動評価し、プロンプトとルールを改善した。
