## 製品概要
### 背景(製品開発のきっかけ、課題等）
昨今の就活では選考の過程でグループディスカッション(GD)が用いられることが多い。   
しかし、GDには致命的な欠点がある。  

それは司会の存在である。

司会はその他の役割に比べて明らかに異質な存在である。こなさないといけない役割も多く、必然的に膨大な発言量になる。  
司会を有利な立ち位置だと思ったことがある人も少なくないだろう。  
一方で、司会は自分の意見を言いづらく、負担が大きいという側面もある。司会の仕事で話す量が増えてしまうため、自分の意見まで言うタイミングを失いがちだ。  
また、司会は立場上、発言量の少ない人に話を振る必要があるが、相手の気持ちを思いやりながら話を円滑に進めるのは並大抵のことではない。   

このようにの司会の役割は不公平を生む。不幸も生む。 

そこで不公平と不幸をなくすため、進行役をAIに任せるという発想にたどり着いた。  
進行役をAIに任せれば、すべての参加者が平等な立場として心置きなく意見を出せる。  
言葉数が少ない人に話を振る際も、AIは心を痛めない。  
さらに、司会の進行の形式はある程度決まっているためAIに代替させても全く問題がない。

おまけに、このプロダクトをつかうことで、タイムキーパーという~~あまりに楽すぎる~~役割も同時に担ってくれる。

### 製品説明(具体的な製品の説明)
PC に向かい、マイクとスピーカーを共有して、学生3〜4人と AI でGDを行います。使う人(採用担当者や練習する学生)は、テーマと制限時間などを設定するだけです。

1. **モード選択**: 「人間だけ」「AI 参加者あり」「雑談」から選びます。
2. **設定**: テーマ(AI による自動生成も可能)、制限時間、参加者の人数と名前、議論タイプ(課題解決型、アイデア創出型、意思決定型、計画立案型、指定なし)、スタイル(就活/就活以外/カスタム)を決めます。必要なら、AI の介入の度合いを項目ごとに調整できます。
3. **進行**: 参加者の自己紹介の声を登録しておくと、以降の発言が誰のものかを判別します。AI の進行役は、議論の状況を見ながら、必要なときだけ音声で話しかけます。参加者のカードの幅は、発言量に応じて伸び縮みします。
4. **振り返り**: 終了後に、喋った量、発言の種類(提案、根拠、質問、反論など)の回数、練習用のフィードバックを確認できます。点数は出さず、選考の評価には使わないことを明記しています。

### 特長
#### 1. 「介入しない」も選べる、AI の自律判断
AI は、何を話すかだけでなく、そもそも今話すべきかを判断します。盛り上がっている最中には割り込まず、停滞・脱線・対立・発言の偏りなど、介入しないと議論の質が下がる場面だけで話します。迷ったときは介入しません。論点整理や深掘りの質問はしますが、解決策や正解は言わず、特定の結論へも誘導しません(議論促進型)。

#### 2. 声で人を見分けて、公平に話を振る
自己紹介の声を登録して、発言ごとに照合します。長く発言していない人には、話題の区切りで名前を呼んで話を振ります。識別の自信が低いときは、個人を指名せずに全体へ呼びかけます。発言量はカードの幅で見えるので、話しすぎ・話さなすぎに自分で気づけます。

#### 3. 用途に合わせて調整でき、1人でも練習できる
就活のグループディスカッション、一般的なグループワーク、雑談など、用途に応じてAIの進行スタイルを選べます。議論の場面では、AIの介入の度合いも細かく調整できます。人間が少ないときは、AI参加者がテーマに対する異なる立場を自動で受け持ち、議論に加わります。AI参加者のレベルも選べるので、練習相手として使えます。

### 解決出来ること
- 司会役の負担と、役割による不公平の軽減
- 議論の停滞・脱線・発言の偏りへのその場での対処
- 時間管理(残り時間の告知と終了)
- GDの練習相手がいないときの、1人での練習と振り返り

### 今後の展望
- スマホアプリ化(現在は、スマホの画面比率に合わせたWebアプリ)
- オンライン会議への対応(通話システムとの連携)
- 発話のかぶりの解消(誰が先に話すかの調整)
- 遮られた人に話を戻す機能(検出は未実装)
- 議論の結論の候補を、AI が比較・整理して提案する機能
- 議事録の整形と書き出し
- 就活以外の用途(授業、会議など)の拡充

### 注力したこと(こだわり等)
- **「介入しない」判断を重視したAI司会者**: AIが何を話すかだけでなく、そもそも介入すべきかを判断するように設計しました。停滞・脱線・発言の偏りなどを考慮し、参加者だけで議論が進んでいる場合は見守ります。AIが常に発言するのではなく、必要な場面で支援することを重視しました。
- **LLMとルールを組み合わせた介入制御**: 介入の必要性や発言内容はLLMが柔軟に判断する一方、発話中の割り込み防止、介入間隔、個人指名の条件、発言内容の制限などはルールで制御しました。LLMの判断結果もそのまま採用せず、検証・補正することで、過剰介入や不適切な発言を抑制しています。
- **用途に応じた介入ポリシー**: 就活GDでは参加者自身の思考や議論を尊重し、AIが解決策や新しい論点を安易に提示しないよう制限しています。一方、一般的なグループワークでは、必要に応じて内容面のヒントも提供できます。進行・脱線修正・論点整理・発言機会・停滞・内容支援の度合いやタイミングを個別に調整できる仕組みを実装しました。
- **雑談専用のAI司会者**: GD・GWの議論促進型とは別に、初対面の場を和ませる雑談専用のAI司会者を開発しました。雑談では、AIが自発的に話題提供・深掘り・橋渡し・話題転換を行い、参加者同士の会話が始まれば自然に介入を控えます。会話の流れや参加者の反応に応じて、AIが積極的に場を回す状態と見守る状態を切り替える仕組みを設けました。
- **失敗したときは「介入しない」に倒す設計**: AI の応答が失敗しても、変な発言をしません。話者識別が不安定でも、全体の進行は止まりません。
- **待たせない工夫**: AI の判断には数秒かかるため、生成しながら一文ずつ読み上げます。話し始める直前にも、誰かが話し始めていないか確認します。
- **実測に基づく方針の転換**: AssemblyAI の話者分離は日本語のリアルタイム用途では使えなかったため、自己紹介の声を登録して照合する方式に切り替えました。
- **AI 自身の声の回り込み対策**: AI の発話中もマイクの音を文字起こしに送りつつ、AI 自身の声の回り込みは捨てます。
- **シナリオ評価を通じた継続的な改善**: 停滞・脱線・発言の偏り・参加者からの依頼などを想定した29種類の議論シナリオで、AIの判断を自動評価しました。モックによる回帰テストに加え、実際のClaude APIによる判断も検証し、発見した問題をもとにプロンプトとルールの両面から改善しました。雑談モードについても、複数ターンの会話シナリオを用いて、話題転換や過剰介入などの問題を検証しました。

## 開発技術
### 活用した技術
#### API・データ
* Anthropic API(Claude Opus 5.5): 議論の分析と介入の判断、AI 参加者の発言、テーマ生成、振り返りの生成
* AssemblyAI Streaming API(Universal-3.6 Pro): 日本語のリアルタイム文字起こし

#### フレームワーク・ライブラリ・モジュール
* Python 3.14、FastAPI、uvicorn、WebSocket、pydantic
* sherpa-onnx(3D-Speaker CAM++): 声の照合による話者識別
* sounddevice、numpy、websocket-client
* pytest(ルール層・進行のテスト)
* フロントエンドは、単一の静的HTML(`app/static/index.html`)

#### デバイス
* PC(macOS で動作確認。Windows 向けの音声合成にも対応)
* マイク1本、スピーカー
* 音声合成: macOS 標準の `say`、Windows 標準の音声合成
